# Provision 0.162.1

Reviewed against Codex CLI and shared app-server 0.162.1. The Codex 0.144.0
minimum remains.

- Fixes discussions that stopped advancing after their first detail fetch.
  Streaming edits and later turns now follow the session revision without a
  page refresh, and interrupted detail requests can retry after reconnect.
- Preserves an explicit native Codex Ultrafast selection when Provision's Fast
  toggle is enabled or disabled, for both HTTP and WebSocket requests.
- Adds regression coverage for Codex's partial-answer phase and consolidated
  command output. All 34 probed app-server methods remain available; account
  and quota response schemas and normalized model-picker metadata are unchanged.
- Incorporates the reviewed development dependency updates for coverage,
  mypy, and Ruff from PRs #22–24.

Provision continues to isolate interactive Codex launches with `--no-daemon`
and retains one-second freshness for native TUI quota reads alongside its own
hourly full-usage schedule. Codex's automatic quota polling still shares the
`/status` endpoint. Full paginated-history coverage remains unverified.

Validation: 332 Python tests; 82 UI checks; Ruff lint and formatting; strict
mypy checks across 12 boundaries; source/wheel builds and a clean wheel install;
real WebSocket/Chromium discussion updates;
Codex 0.162.1 HTTPS account routing, model discovery, ephemeral thread startup,
and embedded TUI bootstrap using a disposable copy of current credentials.
No model turn or interactive `/status` invocation was run.

See [the compatibility review](https://github.com/jeremydixon22/provision/blob/Provision-v0.162.1/docs/codex-0.162.1-compatibility-review.md)
for evidence and limits. Restart Provision after upgrading so the daemon loads
this release.
