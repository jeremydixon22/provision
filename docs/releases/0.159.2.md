# Provision 0.159.2

Reviewed against Codex CLI 0.159.2. The Codex 0.144.0 minimum remains.

- Restores fresh quota checks from a Provision-managed Codex TUI's `/status`
  command. Native TUI usage reads use a one-second minimum interval, while
  Provision's own full-usage refresh keeps its hourly schedule.
- Keeps Provision-managed interactive, resume, and fork sessions on an embedded
  Codex app-server. Codex's new shared daemon does not isolate clients'
  environments; the embedded path preserves Provision's HTTPS trust bundle and
  profile/session routing. Older Codex CLIs keep their prior launch path.
- Adds GPT-6.1 Sol to the fallback model picker and selects the highest-priority
  bundled model for profiles without an explicit choice, matching Codex's new
  default while preserving saved selections.
- Reduces the dashboard wordmark to 166 × 33 px at all breakpoints.

Codex's periodic TUI quota requests still use the same endpoint as `/status`
and may cause frequent upstream reads near quota exhaustion. This does not
establish that quota checks consume model allowance. Provision's JSONL history
reader recovered turns from recent paginated rollouts, but full page/segment
coverage remains unverified. Shared-daemon `agents` and `queue` commands should
be used through the native `codex` CLI.

Validation: 329 Python tests; 72 UI checks; Ruff lint and formatting; strict
mypy boundary checks; source and wheel builds with a clean wheel install;
isolated Codex 0.159.2 HTTPS `account/read` and TUI bootstrap smoke test. The
generated app-server schema retains all 34 methods Provision probes.

See [the compatibility review](https://github.com/jeremydixon22/provision/blob/Provision-v0.159.2/docs/codex-0.159.2-compatibility-review.md)
for protocol coverage and limits. Restart Provision after upgrading so the
running daemon loads this release.
